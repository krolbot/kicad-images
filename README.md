# KiCad toolkit

Один образ: браузерный KiCad, MCP по stdio или аутентифицированному Streamable HTTP, официальный `kicad-cli`, инструменты автоматизации и дополнения PCM. Для HTTP тот же образ запускается отдельным минимально привилегированным сервисом; версии CAD и MCP не расходятся.

## Состояние

Подготовлен единый `Dockerfile` с Freerouting 2.5.0 и защитой исходной меди при выборочном импорте; изменения проверяются без автоматической сборки и запуска CAD-образа. Публикация нового монолитного образа запускается **только вручную** через GitHub Actions → **KiCad toolkit** → **Run workflow**. Наличие исходников не означает, что новый тег уже опубликован.

Тег следующей сборки: `ghcr.io/krolbot/kicad-gui:10.0.8-0.21.1-fr2.5.0-tools11`. Каждая сборка также публикует `sha-<полный SHA коммита>` и OCI-метку `org.opencontainers.image.revision`.

Основа — LinuxServer.io Selkies на Ubuntu 26.04, закреплённая по digest. KiCad и штатные библиотеки устанавливаются из [официального PPA KiCad 10](https://www.kicad.org/download/linux-distros/#_ubuntu) с точной версией пакетов `10.0.8~ubuntu26.04.1`. Ключ PPA включён в `apt/keyrings/kicad.asc`; его отпечаток `FDA854F61C4D0D9572BB95E5245D5502FAD7A805` и подпись индекса проверены. APT использует отдельный `Signed-By`, без отключения проверки подписей. GUI, CLI, Python `pcbnew` и MCP используют **один KiCad 10.0.8**. Браузерный рабочий стол запускает менеджер KiCad; по умолчанию выбран X11, Docker внутри контейнера отключён. Старые раздельные теги остаются историческими сборками.

## Состав

### Основные программы

- KiCad: менеджер проектов, Eeschema, Pcbnew, штатные библиотеки, 3D-просмотр, `kicad-cli` и системный `pcbnew`.
- MCP: `mcp-server-kicad==0.21.1`, отдельное Python-окружение **в том же образе**.
- Маршрутизация: Freerouting 2.5.0 с точечным backport [PR974](https://github.com/freerouting/freerouting/pull/974), Java 25. В официальном JAR заменён только `FoundConnectionInserter.class`; fanout включён при `automatic_neckdown=false`, `max_passes` ограничивает fanout и автороутер, а оптимизатор выключен. При `autoroute_pcb(nets=...)` исходные `segment`/`arc`/`via` сохраняются с исходными UUID и геометрией; из результата добавляется только новая медь выбранных цепей.
- Автоматизация: KiKit 1.8.1, PcbDraw 1.3.0, SKiDL 2.3.0, WireViz 0.4.1, KiCost 1.1.21, KiBot 1.9.1, KiAuto 2.3.10, KiDiff 2.6.0, KiBoM 1.9.1.
- Расчёты и выпуск документации: ngspice, NumPy, SciPy, Shapely, Graphviz, Cairo, ReportLab, Ghostscript, Inkscape, ImageMagick, MuPDF, Poppler, librsvg, OpenSCAD, Xvfb, xdotool.
- Графические зависимости дополнений: системный wxPython; PySide6 6.11.1 устанавливается из готовых Linux-колёс только в окружения двух Qt-плагинов. `ibom` запускает генератор InteractiveHtmlBom из закреплённого пакета.

KiCost может обращаться к поставщикам; отсутствие учётных данных ограничивает доступные источники цен. Ключи не входят в образ. Возможность устанавливать и запускать локальные инструменты не означает, что внешние сервисы работают без подключения и авторизации.

### PCM: 26 плагинов и 5 библиотечных пакетов

Точные идентификаторы, версии, ограничения KiCad, URL и SHA-256: [`addons.lock.json`](addons.lock.json). Источник — [официальные метаданные KiCad](https://gitlab.com/kicad/addons/metadata); Espressif закреплён по официальному архиву производителя. Все 31 архива были скачаны, проверены по SHA-256 и безопасно распакованы при проверке исходников.

- Производство и варианты: KiKit frontend 1.6.0, InteractiveHtmlBom 2.12.0, KiVar 0.5.6, Gerber Zipper 2 2.0.7, prefab-gate 0.2.0.
- Размещение: Replicate Layout 5.0.1, Place Footprints 5.0.0, Testpoints 0.1.11, Parts Placer 0.1.14 с точечным [исправлением вызова Flip для KiCad 10](patches/parts-placer-kicad10.patch), PosOrient 2.0.0, Component Position Exporter 1.0.1. Архив Parts Placer проверяется по исходному SHA-256, затем применяется явный патч; алгоритм размещения не заменён.
- Плата и соединения: Localize Dependencies 1.0.1, Via Stitching 4.0.0, ViaFence 1.1.0, HoleFinder 1.1, Fanout Tool 1.0.0, RF-Tools 1.3.2, pcb-action-tools 1.0.7, NCCM 0.1.3, Z0 Field Solver 0.3.0.
- Оформление и документация: KiBuzzard 1.7.0, Kobee Studio 1.4.1, Silk Reference Tools 2.1.0, KiNotes 1.5.2, Pinout Image Generator 1.4.0, Pinout Generator 1.2.
- Библиотеки: KiKit Library 1.6.0, Espressif 3.2.1, SparkFun 10.0.0, Arduino Modules 4.2.0, FabLib 0.0.3.

KiKit PCM frontend и библиотека имеют собственную нумерацию выпусков, отличную от Python backend. Это не две установленные версии Python backend.

Не добавлены намеренно:

- Save/Restore Layout: опубликованные ограничения совместимости не подходят к KiCad 10; для повторения размещения включён Replicate Layout.
- Parasitics: текущий численный стек требует `scipy<1.15`, несовместимый с Python 3.14 выбранной базы. Наличие пакета в PCM не гарантирует совместимость его зависимостей.
- Загрузчики производителям, облачные DFM/AI-сервисы и дополнения с отдельной оплатой или обязательными учётными данными.
- FreeCAD, Blender, StepUp, pcb2blender и другие отдельные MCAD-приложения. Штатный STEP-экспорт KiCad остаётся доступен.

## Установка дополнений и сохранность настроек

При сборке архивы проверяются и помещаются в `/opt/kicad-addons`. `KICAD_DOCUMENTS_HOME=/config/.local/share` согласует каталог PCM с официальным поиском плагинов KiCad. Десять IPC-плагинов получают отдельные подготовленные Python-окружения с системными графическими библиотеками. Это штатная схема KiCad 10, а не новый мост или обработчик MCP. SDK закреплён на 0.8.0, у Kobee Studio — на требуемом им 0.7.1; protobuf и pynng также закреплены.

Перед запуском GUI LinuxServer init hook работает от пользователя `abc`:

- добавляет отсутствующие пакеты и полную регистрацию PCM в постоянный `/config`;
- не заменяет пользовательскую версию пакета, ручную установку, существующие таблицы библиотек и Python-окружения;
- создаёт таблицы штатных и дополнительных библиотек для новой конфигурации;
- добавляет только отсутствующие настройки путей; сохраняет ссылки старых библиотек через обнаруженные `KICAD6/7/8/9_*` переменные;
- включает локальный IPC API для новой конфигурации и указывает `/usr/bin/python3`; существующее явное отключение API или выбранный интерпретатор сохраняет;
- копирует подготовленные IPC-окружения в штатный пользовательский каталог кэша, не заменяя уже существующие.

Если пользователь отключил API или автоматическое добавление библиотек, соответствующие возможности потребуют его явного включения. Повреждённая регистрация PCM вызывает ошибку вместо потери настроек. Глобальные библиотеки для воспроизводимого проекта не заменяют проектные `sym-lib-table` и `fp-lib-table`.

При переносе `/config` с Alpine на Ubuntu старые Python-окружения IPC-плагинов нужно пересоздать: одинаковая версия Python не делает нативные модули musl и glibc совместимыми. Init hook не удаляет пользовательский кэш автоматически.

## Использование после сборки

Один контейнер с постоянными `/config` и `/projects` запускается как обычный LinuxServer KiCad. Браузерный интерфейс наследует настройки и порты базового образа. Не выставляйте рабочий стол в Интернет без защищённого доступа.

MCP по stdio запускается внутри GUI-контейнера:

```sh
docker exec --user abc --workdir /projects -i kicad /usr/local/bin/kicad-mcp
```

Штатное имя `mcp-server-kicad` также ведёт в расширенный сервер: существующие клиенты не обходят новые команды.

Имя `kicad` здесь — имя вашего контейнера. Для stdio не добавляйте `-t`. Docker socket внутри CAD-контейнера не требуется. Команда `docker exec` выполняется на Docker-хосте, а не из другого контейнера с выданным ему сокетом.

Для постоянного Streamable HTTP запускайте **тот же digest образа** отдельным сервисом с переопределённой точкой входа:

Точка входа запускает закрытый Xvfb внутри HTTP-контейнера: `pcbnew` получает обязательный X Display для заливки зон, но MCP не получает доступ к графической сессии основного KiCad и не открывает X11 по TCP.

```yaml
user: "1000:1000"
entrypoint: ["/usr/local/bin/kicad-mcp-http"]
security_opt:
  - no-new-privileges:true
cap_drop:
  - ALL
environment:
  KICAD_MCP_BEARER_TOKEN: ${KICAD_MCP_BEARER_TOKEN:?required}
  KICAD_MCP_ALLOWED_HOSTS: kicad-mcp.example.com,kicad-mcp-http:8000
  KICAD_MCP_ALLOWED_ORIGINS: https://kicad-mcp.example.com
```

Сервис слушает `0.0.0.0:8000`, публикует MCP на `/mcp` и отвергает запуск без `KICAD_MCP_BEARER_TOKEN`. Все HTTP-запросы требуют единственный точный заголовок `Authorization: Bearer …`; токен не передаётся в аргументах процесса и не входит в образ. Встроенная защита от DNS rebinding принимает только явно заданные `Host` и `Origin`. Наружу сервис следует выводить через HTTPS reverse proxy, не через Docker `ports`.

CLI-инструменты доступны в том же контейнере: `kicad-cli`, `kikit`, `pcbdraw`, `kibot`, `wireviz`, `kicost`, `freerouting`, `ibom`.

### Дополнительные MCP-команды

Адаптер `toolkit_mcp.py` сохраняет все **109 штатных команд** MCP 0.21.1 и добавляет типизированные команды набора инструментов, включая:

- `get_toolkit_status` — версии установленных движков и закреплённых PCM-пакетов.
- `download_project_file` — точные байты одного обычного файла из `/projects` в стандартном MCP `EmbeddedResource`: base64, MIME-тип, размер и SHA-256. Абсолютные пути вне `/projects`, `..`, симлинки, каталоги и файлы больше 16 MiB отвергаются.
- `list_project_files`, `stat_project_path`, `create_project_directory`, `upload_project_file`, `copy_project_path`, `move_project_path`, `delete_project_path`, `create_project_archive`, `extract_project_archive` — полный файловый цикл в `/projects`. Запись и удаление защищены SHA-256; ZIP ограничен 10 000 элементами и 512 MiB, не допускает traversal, ссылок, дубликатов и опасной степени сжатия.
- `get_schematic_items` / `edit_schematic_items` — полное чтение и CAS-редактирование по UUID шин, входов шин, текста, текстовых блоков, линий, полилиний, прямоугольников, окружностей, дуг и изображений. S-expression элемента возвращается и принимается без потери неизвестных полей; перед публикацией схема открывается штатным KiCad.
- `get_board_items` / `edit_board_items` — полное чтение и CAS-редактирование по UUID графики, текста, размеров, зон, keepout/rule-area, изображений и размещённых посадочных мест. `get_board_section` / `replace_board_section` управляют `general`, `paper`, `layers` и полным `setup`, включая stackup и настройки платы; кандидат проверяется через системный `pcbnew`.
- `get_footprint_definition` / `replace_footprint_definition` — полная native-структура `.kicad_mod`: графика, текст, свойства, padstack, сложные площадки и 3D-модели. Существующие `create_footprint` / `edit_footprint` остаются коротким типизированным путём для SMD/PTH/NPTH, отверстий и пазов.
- `get_project_settings` / `replace_project_settings`, `get_project_library_table` / `replace_project_library_table`, `get_design_rules` / `replace_design_rules` — полные `.kicad_pro`, `sym-lib-table`, `fp-lib-table` и `.kicad_dru` с CAS и сохранением полей KiCad 10. URI библиотек ограничены проектом и закреплёнными системными библиотеками.
- `manufacture_pcb` — KiBot: Gerber, Excellon, координаты компонентов и PDF; `outputs` выбирает нужные виды.
- `generate_interactive_bom` — автономный HTML InteractiveHtmlBom с данными платы, без запуска браузера.
- `panelize_pcb` — сетка KiKit с перемычками; размеры, зазоры и способ отделения заданы типизированными параметрами.
- `discover_replication` — иерархия выбранного опорного компонента, допустимые назначения и параметры Replicate Layout.
- `replicate_layout` — повтор размещения/трассировки через **Replicate Layout 5.0.1**. Используйте `level_index` и точные `destination_sheets` из предварительного обнаружения.
- `place_footprints` — линейное, круговое или матричное размещение через **Place Footprints 5.0.0**. `references` задаёт порядок; `anchor_ref` должен входить в список.
- `place_parts` — координаты, поворот, сторона и необязательная группа через **Parts Placer 0.1.14**. Входные координаты декартовы: движок преобразует `(x,y)` в `(origin_x+x, origin_y-y)` в координатах KiCad, миллиметры.
- `scan_project_dependencies` — список зависимостей и ключей выбора через **Localize Dependencies 1.0.1**.
- `localize_project_dependencies` — локализация выбранных зависимостей **на копии проекта**, при необходимости ZIP. Штатные библиотеки включаются только явно: `include_standard=true`.
- `get_board_edit_state` — SHA-256 и native-состояние footprint/pad/track/via по UUID; фильтры по точным net/reference, при необходимости полный DRC с разрывами.
- `edit_board_copper_batch` — ограниченный пакет move/remove-by-UUID/add trace/via и необязательный `autoroute_pcb(nets=...)`. Элемент `moves` имеет вид `{"reference":"J1","x_mm":100.45,"y_mm":75.5,"rotation_deg":-90,"layer":"F.Cu"}`; `layer` необязателен, принимает только `F.Cu`/`B.Cu` и при смене стороны вызывает штатный native flip KiCad до установки итогового угла. Пакеты без `layer` сохраняют прежнее поведение. Сначала выполняется native dry-run на временной копии, refill/reopen, полный DRC и проверка защищённых UUID/net/pad; запись в исходный PCB требует повторного идентичного вызова с `dry_run=false`, CAS `expected_sha256` и выданным `confirmation_token`.

Все проектные пути абсолютные, внутри `/projects`; разрешены только явно перечисленные read-only корни системных библиотек KiCad и PCM. Правило применяется и к 109 штатным командам. Ссылки `Sheetfile` во всей достижимой иерархии разбираются CST-парсером перед штатным вызовом: абсолютные пути, `..`, симлинки и выход из `/projects` отвергаются. `create_project`, `create_schematic` и `create_symbol_library` сначала создают результат в закрытом временном каталоге, а затем публикуют новые файлы через закреплённый родительский дескриптор без замены существующих файлов. Любой старый инструмент, меняющий существующий файл, требует `expected_sha256`; для `set_net_class` это SHA-256 реально изменяемого `.kicad_pro`, а `add_hierarchical_sheet` отдельно требует SHA-256 родительской, дочерней и, когда она отличается, корневой схемы. `update_pcb_from_schematic` использует обязательный различимый объект `publication`: `{"mode":"create"}` создаёт отсутствующую плату во временном каталоге и публикует её без замены, а `{"mode":"update","expected_sha256":"…"}` меняет только существующую плату с CAS. `create_sym_lib_table`, `flatten_hierarchy` и `run_jobset` также имеют CAS, а URI старой таблицы библиотек проходят ту же проверку, что и новый полный редактор. Все старые штатные экспортёры и `autoroute_pcb` требуют явный новый `output_dir` (для `export_ipc2581` — новый `output`). Локальные производственные, конвертационные и рендеринговые инструменты, а также Localize Dependencies и KiNotes, применяют тот же контракт полного закрытого временного каталога и публикации без замены: движок пишет в закрытый временный каталог, после чего только обычные файлы публикуются атомарно через `renameat2(RENAME_NOREPLACE)` или жёсткую ссылку. Неудачный post-route DRC отбрасывает результат autoroute вместо публикации платы без отчёта. Общий `flock` в `/projects` согласует HTTP- и GUI-контейнеры, использующие один том. Он защищает сотрудничающие MCP-процессы; несохранённое состояние GUI и запись процессом, игнорирующим lock/CAS, не являются защищённым файловым состоянием. Файловый цикл, архивы и публикация отредактированных KiCad-файлов используют операции `openat`/`renameat` относительно закреплённых файловых дескрипторов с `O_NOFOLLOW`, поэтому подмена родительского каталога симлинком между проверкой и записью не уводит запись за `/projects`. `download_project_file` читает файл через symlink-free файловые дескрипторы с пределом 16 MiB. `run_jobset` требует SHA-256 всего каталога проекта, принимает только относительные пути внутри него, отвергает поля команд, shell, Python, конфигурации KiBot, скриптов и hooks, выполняет KiCad в закрытой копии проекта и публикует только новые обычные файлы без замены; изменение или удаление существующего файла отбрасывает весь результат. Параметры опубликованы в MCP JSON Schema; произвольный shell или Python-код не принимается.

Ограничения Localize Dependencies сохранены: сканируются CAD-файлы верхнего уровня каталога; символы локализуются целыми библиотеками, посадочные места — по выбранным элементам. Входной проект не должен содержать симлинков. Источники зависимостей ограничены `/projects` и библиотеками образа (`/usr/share/kicad`, `/opt/kicad-addons`); произвольные файлы конфигурации контейнера в архив не попадают. ZIP — стандартная упаковка уже локализованной копии, а не отдельная функция плагина.

Это интеграция указанного набора, **не универсальный вызов всех GUI-плагинов**. Сохранённое состояние файлов, несохранённая плата в GUI и IPC — разные состояния. Для электрической проверки результата используйте штатные ERC/DRC; успешный выпуск файлов не означает пригодность платы к производству.

Владелец каталога `/projects` должен соответствовать выбранным `PUID`/`PGID`. Init hook не меняет владельцев рабочих проектов. Версии KiCad, штатных библиотек, основных Python-программ и архивы закреплены; остальные зависимости APT и Python разрешаются из выбранных репозиториев при сборке, поэтому побитовая воспроизводимость сборки не заявляется.

## Проверка исходников и сборка

Без Docker и запуска KiCad:

```sh
python3 -m venv .venv
```

Отдельная проверка реальных архивов без выполнения кода плагинов:

```sh
python3 pcm.py build addons.lock.json /path/to/empty/bundle
```

Сборка единственного образа, когда она нужна:

```sh
docker build -t kicad-toolkit .
```

При реальной сборке `mcp_http_smoke.py` сначала требует отказ `401` без токена, затем выполняет настоящие `initialize`, `tools/list` и `tools/call` по Streamable HTTP с Bearer-токеном. Он скачивает двоичный файл с пробелом в имени, сверяет точные байты и SHA-256 и требует отказа для traversal и симлинка. `mcp_toolkit_smoke.py` проверяет ненулевые файлы выпуска, HTML BOM, панель, три способа размещения, геометрию репликации на закреплённом upstream-проекте и локализацию с ZIP. Тестовые исходники проверяются на неизменность; отрицательные запросы не должны оставлять результат. `native_ipc_smoke.py` отдельно запускает настоящий Pcbnew с временным профилем и требует ответ `kipy.KiCad().get_version()` той же версии. `mcp_autoroute_smoke.py` сохраняет проверку Freerouting. `mcp_smoke.py` требует точного совпадения версий CLI и системного `pcbnew` с `KICAD_VERSION`, затем открывает MCP-сессию и проверяет основные методы, версию KiCad и чтение стандартного символа. Проверки исходников, SHA-256 и зависимостей **не подтверждают** запуск браузера, действия GUI-плагинов, трассировку или расчёт реальной платы. Эти проверки требуют отдельного разрешённого запуска образа.

Автоматического развёртывания нет. Конфигурация серверов, учётные данные и рабочие проекты в репозиторий не входят. Публичность GHCR настраивается отдельно; новый тег нельзя считать опубликованным до успешного ручного задания и проверки реестра.
