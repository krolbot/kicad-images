# KiCad toolkit

Один контейнер: браузерный KiCad, MCP по stdio, официальный `kicad-cli`, инструменты автоматизации и дополнения PCM. Отдельный MCP-контейнер больше не нужен.

## Состояние

Подготовлен единый `Dockerfile`; изменения проверяются без сборки и запуска CAD-образа. Публикация нового монолитного образа запускается **только вручную** через GitHub Actions → **KiCad toolkit** → **Run workflow**. Наличие исходников не означает, что новый тег уже опубликован.

Тег следующей сборки: `ghcr.io/krolbot/kicad-gui:10.0.7-0.21.1-fr2.1.0-tools4`. Каждая сборка также публикует `sha-<полный SHA коммита>` и OCI-метку `org.opencontainers.image.revision`.

Основа — LinuxServer.io Selkies на Ubuntu 26.04, закреплённая по digest. KiCad и штатные библиотеки устанавливаются из [официального PPA KiCad 10](https://www.kicad.org/download/linux-distros/#_ubuntu) с точной версией пакетов `10.0.7~ubuntu26.04.1`. Ключ PPA включён в `apt/keyrings/kicad.asc`; его отпечаток `FDA854F61C4D0D9572BB95E5245D5502FAD7A805` и подпись индекса проверены. APT использует отдельный `Signed-By`, без отключения проверки подписей. GUI, CLI, Python `pcbnew` и MCP используют **один KiCad 10.0.7**. Браузерный рабочий стол запускает менеджер KiCad; по умолчанию выбран X11, Docker внутри контейнера отключён. Старые раздельные теги остаются историческими сборками.

## Состав

### Основные программы

- KiCad: менеджер проектов, Eeschema, Pcbnew, штатные библиотеки, 3D-просмотр, `kicad-cli` и системный `pcbnew`.
- MCP: `mcp-server-kicad==0.21.1`, отдельное Python-окружение **в том же образе**.
- Маршрутизация: Freerouting 2.1.0, Java 21, закреплённый JAR с проверкой SHA-256.
- Автоматизация: KiKit 1.8.1, PcbDraw 1.3.0, SKiDL 2.3.0, WireViz 0.4.1, KiCost 1.1.21, KiBot 1.9.1, KiAuto 2.3.10, KiDiff 2.6.0, KiBoM 1.9.1.
- Расчёты и выпуск документации: ngspice, NumPy, SciPy, Shapely, Graphviz, Cairo, ReportLab, Ghostscript, Inkscape, ImageMagick, MuPDF, Poppler, librsvg, OpenSCAD, Xvfb, xdotool.
- Графические зависимости дополнений: системный wxPython; PySide6 6.11.1 устанавливается из готовых Linux-колёс только в окружения двух Qt-плагинов. `ibom` запускает генератор InteractiveHtmlBom из закреплённого пакета.

KiCost может обращаться к поставщикам; отсутствие учётных данных ограничивает доступные источники цен. Ключи не входят в образ. Возможность устанавливать и запускать локальные инструменты не означает, что внешние сервисы работают без подключения и авторизации.

### PCM: 26 плагинов и 5 библиотечных пакетов

Точные идентификаторы, версии, ограничения KiCad, URL и SHA-256: [`addons.lock.json`](addons.lock.json). Источник — [официальные метаданные KiCad](https://gitlab.com/kicad/addons/metadata); Espressif закреплён по официальному архиву производителя. Все 31 архива были скачаны, проверены по SHA-256 и безопасно распакованы при проверке исходников.

- Производство и варианты: KiKit frontend 1.6.0, InteractiveHtmlBom 2.12.0, KiVar 0.5.6, Gerber Zipper 2 2.0.7, prefab-gate 0.2.0.
- Размещение: Replicate Layout 5.0.1, Place Footprints 5.0.0, Testpoints 0.1.11, Parts Placer 0.1.14, PosOrient 2.0.0, Component Position Exporter 1.0.1.
- Плата и соединения: Localize Dependencies 1.0.1, Via Stitching 4.0.0, ViaFence 1.1.0, HoleFinder 1.1, Fanout Tool 1.0.0, RF-Tools 1.3.2, pcb-action-tools 1.0.7, NCCM 0.1.3, Z0 Field Solver 0.3.0.
- Оформление и документация: KiBuzzard 1.7.0, Kobee Studio 1.4.1, Silk Reference Tools 2.1.0, KiNotes 1.5.2, Pinout Image Generator 1.4.0, Pinout Generator 1.2.
- Библиотеки: KiKit Library 1.6.0, Espressif 3.2.1, SparkFun 10.0.0, Arduino Modules 4.2.0, FabLib 0.0.3.

KiKit PCM frontend и библиотека имеют собственную нумерацию выпусков, отличную от Python backend. Это не две установленные версии Python backend.

Не добавлены намеренно:

- Save/Restore Layout: опубликованные ограничения совместимости не подходят к KiCad 10; для повторения размещения включён Replicate Layout.
- Parasitics: текущий численный стек требует `scipy<1.15`, несовместимый с Python 3.14 выбранной базы. Наличие пакета в PCM не гарантирует совместимость его зависимостей.
- Загрузчики производителям, облачные DFM/AI-сервисы и дополнения с отдельной оплатой или обязательными учётными данными.
- FreeCAD, Blender, StepUp, pcb2blender и другие отдельные MCAD-приложения. Штатный STEP-экспорт KiCad остаётся доступен.

## Установка дополнений и сохранность настроек

При сборке архивы проверяются и помещаются в `/opt/kicad-addons`. `KICAD_DOCUMENTS_HOME=/config/.local/share` согласует каталог PCM с официальным поиском плагинов KiCad. Десять IPC-плагинов получают отдельные подготовленные Python-окружения с системными графическими библиотеками. Это штатная схема KiCad 10, а не новый мост или обработчик MCP. SDK закреплён на 0.8.0, у Kobee Studio — на требуемом им 0.7.1; protobuf и pynng также закреплены.

Перед запуском GUI LinuxServer init hook работает от пользователя `abc`:

- добавляет отсутствующие пакеты и полную регистрацию PCM в постоянный `/config`;
- не заменяет пользовательскую версию пакета, ручную установку, существующие таблицы библиотек и Python-окружения;
- создаёт таблицы штатных и дополнительных библиотек для новой конфигурации;
- добавляет только отсутствующие настройки путей; сохраняет ссылки старых библиотек через обнаруженные `KICAD6/7/8/9_*` переменные;
- включает локальный IPC API для новой конфигурации и указывает `/usr/bin/python3`; существующее явное отключение API или выбранный интерпретатор сохраняет;
- копирует подготовленные IPC-окружения в штатный пользовательский каталог кэша, не заменяя уже существующие.

Если пользователь отключил API или автоматическое добавление библиотек, соответствующие возможности потребуют его явного включения. Повреждённая регистрация PCM вызывает ошибку вместо потери настроек. Глобальные библиотеки для воспроизводимого проекта не заменяют проектные `sym-lib-table` и `fp-lib-table`.

При переносе `/config` с Alpine на Ubuntu старые Python-окружения IPC-плагинов нужно пересоздать: одинаковая версия Python не делает нативные модули musl и glibc совместимыми. Init hook не удаляет пользовательский кэш автоматически.

## Использование после сборки

Один контейнер с постоянными `/config` и `/projects` запускается как обычный LinuxServer KiCad. Браузерный интерфейс наследует настройки и порты базового образа. Не выставляйте рабочий стол в Интернет без защищённого доступа.

MCP запускается внутри **этого же** контейнера:

```sh
docker exec --user abc --workdir /projects -i kicad /usr/local/bin/kicad-mcp
```

Имя `kicad` здесь — имя вашего контейнера. Для stdio не добавляйте `-t`. Отдельного сетевого порта MCP и Docker socket внутри CAD-контейнера не требуется. Команда `docker exec` выполняется на Docker-хосте, а не из другого контейнера с выданным ему сокетом.

CLI-инструменты доступны в том же контейнере: `kicad-cli`, `kikit`, `pcbdraw`, `kibot`, `wireviz`, `kicost`, `freerouting`, `ibom`. Плагины GUI **не становятся MCP-методами автоматически**; MCP 0.21.1 сохраняет собственный зарегистрированный набор инструментов. Экспорт KiBot/KiKit или GUI-действие — отдельная операция, а не обещанная возможность MCP.

Владелец каталога `/projects` должен соответствовать выбранным `PUID`/`PGID`. Init hook не меняет владельцев рабочих проектов. Версии KiCad, штатных библиотек, основных Python-программ и архивы закреплены; остальные зависимости APT и Python разрешаются из выбранных репозиториев при сборке, поэтому побитовая воспроизводимость сборки не заявляется.

## Проверка исходников и сборка

Без Docker и запуска KiCad:

```sh
python3 -m unittest -v test_pcm.py
python3 -m compileall -q pcm.py mcp_smoke.py
sh -n root/usr/local/bin/kicad-mcp root/usr/local/bin/freerouting root/usr/local/bin/ibom
bash -n root/custom-cont-init.d/50-kicad-toolkit.sh
```

Отдельная проверка реальных архивов без выполнения кода плагинов:

```sh
python3 pcm.py build addons.lock.json /path/to/empty/bundle
```

Сборка единственного образа, когда она нужна:

```sh
docker build -t kicad-toolkit .
```

При реальной сборке `mcp_smoke.py` требует точного совпадения версий CLI и системного `pcbnew` с `KICAD_VERSION`, затем открывает MCP-сессию и проверяет основные методы, версию KiCad и чтение стандартного символа. Проверки исходников, SHA-256 и зависимостей **не подтверждают** запуск браузера, действия GUI-плагинов, трассировку или расчёт реальной платы. Эти проверки требуют отдельного разрешённого запуска образа.

Автоматического развёртывания нет. Конфигурация серверов, учётные данные и рабочие проекты в репозиторий не входят. Публичность GHCR настраивается отдельно; новый тег нельзя считать опубликованным до успешного ручного задания и проверки реестра.
